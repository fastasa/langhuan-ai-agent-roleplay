# 琅嬛 Langhuan

> 一个本地优先、面向长期角色经营与叙事创作的开源 AI Agent 角色扮演工作台。
>
> An open-source, local-first AI Agent role-playing workspace for persistent characters and evolving worlds.

琅嬛不是一个只负责“把一句提示词发给模型”的聊天壳。它把角色、世界、关系、状态、剧本、地图、提示词和长期记忆拆成可以持续维护的产品资产，再让不同职责的 Agent 围绕同一份上下文协作。

这个仓库是琅嬛的纯净 open 版本：打开后直接进入本地工作区，没有账号、登录、注册、访客模式或管理员后台。

## 从产品经理的视角理解琅嬛

角色扮演产品真正难的，往往不是生成一句好看的回复，而是让一个角色在几十轮、几百轮对话后仍然记得自己是谁、身处哪里、和谁有什么关系，以及哪些事情已经发生。

琅嬛要解决的是这条完整链路：

1. **建立角色**：把身份、性格、经历、关系和表达方式沉淀为可维护资料，而不是散落在一段超长提示词里。
2. **建立世界**：用文档库、世界、场景、舆图和状态系统承载共同事实。
3. **开始扮演**：模型根据当前会话、角色资料和世界上下文生成回复。
4. **保持连续**：召回、编排、审计与提调机制共同处理长对话中的上下文选择和偏差纠正。
5. **继续创作**：编剧、舆图师、造册、鉴心等 Agent 分担不同类型的创作与维护任务。

因此，琅嬛更像一间“AI 角色与世界的长期工作室”，而不是一次性聊天页面。

## 适合谁

- 想长期经营原创角色、OC 或虚拟陪伴角色的人；
- 需要维护复杂世界观、人物关系和连续剧情的创作者；
- 希望自己掌握资料、存档和模型配置的本地 AI 用户；
- 想研究多 Agent 编排、角色记忆和可审查提示词链路的开发者。

当前 open 版本定位为**单机、单工作区、单使用者**。它不是可以直接暴露到公网的多用户 SaaS。

## 产品能力

| 产品模块 | 它解决什么问题 |
| --- | --- |
| 角色与角色组 | 维护角色身份、资料、关系和参与会话的方式 |
| 世界与文档库 | 组织世界设定、知识单元、关系提示和可召回材料 |
| 对话与场景 | 让角色在明确的时间、地点、天气和出场关系中持续互动 |
| 状态、剧本与舆图 | 记录正在发生什么，并把叙事、空间与状态放回同一上下文 |
| 提示词库 | 以可见、可排序、可编辑的方式管理角色扮演提示词 |
| 记忆与召回 | 从长期资料和历史对话中选择本轮真正需要的上下文 |
| Agent 协作 | 由星依、提调、编剧、舆图师、造册、鉴心等不同职责的 Agent 分工处理复杂任务 |
| 编排审计 | 查看模型、步骤和提示词链路，帮助定位角色跑偏或生成异常 |
| 像素工作室 | 在同一项目内制作和管理像素视觉素材 |

## 第一次使用

### 1. 准备环境

需要：

- Windows 10/11（当前优先支持）；
- Node.js 20.19 或更高版本；
- npm 10 或更高版本；
- 一个由你自己提供的 AI 模型服务或已登录的受支持本机 CLI。

### 2. 启动琅嬛

下载或克隆项目后，直接双击根目录的 `启动琅嬛.bat`。

启动器会：

- 首次创建本机 `.env`；
- 缺少依赖时运行 `npm ci`；
- 缺少构建产物时完成生产构建；
- 精确结束占用配置端口的上一份琅嬛服务并等待端口释放；
- 启动本机服务并自动打开浏览器；
- 出错时保留窗口和错误信息。

默认地址是 `http://127.0.0.1:3217`。重复双击启动器会重启正在监听该配置端口的旧服务，其他端口上的程序不受影响。停止服务时，在启动窗口按 `Ctrl+C`。

首次安装依赖需要连接 npm 软件包源，之后普通启动不需要重复安装。

### 3. 配置 AI

进入工作区的“设置 → API 配置”，新建或编辑一个模型预设，填写提供商、模型和必要的 API Key，再测试连接并设为默认预设。

琅嬛支持部署者自行配置的 OpenAI 兼容 HTTPS 端点，也提供部分官方提供商和本机 CLI 的接入方式。不同能力可以使用不同模型预设；密钥只保存在你的本机工作区中。

### 4. 创建第一个角色

首发数据库是空的，不会自动写入样例角色或会话。点击聊天区中央的“新建角色”，先填写最基本的角色信息并保存。

随后可以逐步补充角色资料、关系、提示词和人格内容。没有必要在第一次创建时把所有设定写完；琅嬛的产品思路就是让角色在使用过程中持续生长。

### 5. 建立世界并开始扮演

一个推荐的最短路径是：

1. 新建世界，写下这段故事必须遵守的基础事实；
2. 在文档库中整理地点、势力、人物关系或专有名词；
3. 创建会话，选择角色与世界；
4. 在场景设置中确认时间、地点、天气和出场角色；
5. 开始对话；需要改变剧情方向时使用提调，需要整理设定时交给对应 Agent；
6. 通过提示词日志或编排审计检查模型实际获得了什么上下文。

舆图、剧本、状态、提调和会话设置入口会一直保留；缺少角色、世界或会话时，它们会提示需要补齐的上下文，而不是悄悄消失。

## 本机运行边界

- 一个部署对应一个本地工作区，内部固定作用域为 `local`；
- 服务固定监听 `127.0.0.1`，首发不支持局域网或公网部署；
- 首次启动创建空数据库，不自动写入角色、世界、对话、任务或演示数据；
- 项目没有遥测、作者回传、远程管理入口或跨用户查看能力；
- 未配置第三方 AI、天气服务或主动使用本机 CLI 桥时，不产生对应的外部业务请求；
- `/admin`、`/api/admin/*`、`/api/auth/*` 和 `/api/guest/*` 均明确返回 404。

详细依据见 [隐私说明](PRIVACY.md)、[网络边界](docs/network-boundaries.md)和[架构概览](docs/architecture.md)。

## 数据放在哪里

默认数据库、上传内容和本机密钥位于 `server/data/`；浏览器还会保存少量界面偏好和工作状态。`server/data/` 与 `.env` 都被 Git 忽略。

删除工作区前，请先使用界面中的本地导出功能备份需要保留的内容。不要把数据库、`.env`、密钥、完整对话或包含本机路径的日志提交到公开仓库或 issue。

## 开发者运行方式

开发模式：

```powershell
npm ci
Copy-Item .env.example .env
npm run dev
```

开发界面位于 `http://127.0.0.1:5173`，本机 API 位于 `http://127.0.0.1:3000`。

构建并以单端口运行：

```powershell
npm run build
$env:NODE_ENV = 'production'
npm start
```

生产模式默认地址为 `http://127.0.0.1:3217`。端口可以通过根目录 `.env` 的 `PORT` 调整，监听地址不能通过配置改成公网地址。

## 技术结构

```text
Vue 3 + TypeScript + Pinia
              │
              │ 同源 /api
              ▼
       Node.js + Express
              │
              ├─ SQLite / sql.js 本机数据
              ├─ 本机文件与模型资源
              └─ 用户主动配置的外部 AI 服务
```

项目采用 Vite 构建，服务端固定服务本地工作区。浏览器没有登录恢复流程，服务端也不读取认证 Cookie 或创建用户账号会话。

## 验证

提交改动前运行：

```powershell
npm run verify
```

该命令执行类型检查、服务端测试、浏览器单元测试、生产构建和开源发行扫描。发行扫描以实际 Git 候选文件为准，并检查计划目录、数据库、私钥、许可证正文和构建产物。
