# 星依关系提示编写手册

> 运行时 Skill：`xingyi.relation-hint-authoring`。凡是下一步可能写入 `relationHints`，必须先调用 `readRelationHintSkill`；没有成功读到本手册就停止写入，不能凭记忆猜关系词。

## 一、什么时候必须先读

以下任一动作都属于强制触发：

- 调用 `generateCompilePage`，因为生成整页时会同时写关系提示。
- 调用 `optimizeUnitRelations`。
- 调用 `editUnitCompilePage` 且参数里包含 `relationHints`。
- 新建、补全或修复编译页时，准备判断“关系提示该写什么”。

只改摘要、标签或类型且不传 `relationHints` 时，不需要为了这一项额外读取本手册。

## 二、关系提示的正式作用

- 关系提示是编译页里的语义连线，服务跨目录、跨类型、跨区域召回与关系视图。
- 目录父子结构已经由字段树负责，不能为了“看起来完整”批量复述“父级包含子级、子级属于父级”。
- 正文、摘要或已有可信关系没有明确证据时，不得编造关系。用 `editUnitCompilePage` 补齐关系提示字段时，整组写成 `["无"]`；不要留空数组导致黄灯，也不要用“相关”掩盖无证据。

## 三、唯一允许的写法

### 强关系

```text
[[源单位]]_已登记关系词_[[目标单位]]
```

示例：

```text
[[临川城]]_位于_[[北境]]
[[阿澄]]_效忠于_[[巡夜司]]
[[白塔工坊]]_生产_[[星砂灯]]
```

两端必须各有一组双中括号，中间只有两个分隔下划线。不要加箭头、括号说明、路径或 Markdown 列表符。

### 同名单位的精确引用

标题不能唯一定位时，用正式 ID 消歧：

```text
[[旧城@正式单位ID]]_位于_[[北境@正式单位ID]]
```

`@` 后必须是 `listUnitTree`、`readUnit` 或正式检索工具返回的真实 ID，禁止臆造。标题唯一时优先用纯标题，保持可读。

### 弱关系

```text
[[目标单位]]
```

这是历史兼容写法，只表达“本单位与目标有关”，不表达关系类型和方向。已有弱关系可以保留；新写关系只要证据足够，就优先写强关系。

### 无关系

```text
无
```

只允许作为整组唯一一行，表示已检查但当前没有可证明的关系。不能把“无”和其它关系同时写入。

## 四、谓词和方向

- 只能使用下方运行时附录中的登记词。附录由 `relationPredicateDictionary.ts` 自动生成，是合法谓词唯一真值。
- “正向词”按文本顺序建边：`[[源]]_谓词_[[目标]]`。
- “反向词”虽然按自然中文书写，但解析器会自动归一方向。例如 `[[阿澄]]_属于_[[巡夜司]]` 会归一为“巡夜司包含阿澄”；不要为了迎合内部方向把中文主客体倒着写。
- “双向”关系不区分源和目标的语义方向，但仍要保持一句自然、可读的中文。
- 同一个表面词可能在不同语境中模糊；按正文明确语义选择更具体的登记词，不要只为过校验滥用“相关”。

## 五、取证与编写流程

1. 先成功调用 `readRelationHintSkill`。
2. 用 `listUnitTree`、`readUnit`、`searchWorldText`、`recallSemantic` 等正式只读工具定位源和目标；同名时拿真实 ID。
3. 逐条写出“证据事实 → 合法谓词 → 自然方向”。证据不足就写“无”，不补想象。
4. 写入前检查：
   - 两端是真实存在且能唯一定位的单位；
   - 谓词在附录中；
   - 没有复述纯目录层级；
   - 没有重复、同义重复或互相矛盾的关系；
   - “无”没有和其它行混用。
5. `editUnitCompilePage.relationHints` 是整组覆盖，不是追加。先读出现有整组，把要保留的旧关系与新关系合并、去重后一次传全；不能只传改动的一行。
6. 写入后调用 `diagnoseCompilePages` 复诊受影响单位或子树。红灯按报告逐条修，黄灯补齐字段，再复诊到没有关系提示错误；不能只做状态翻转或口头宣称已修好。

## 六、三个写工具的边界

- `generateCompilePage`：适合编译页整体缺失或用户明确要重新生成整页；会覆盖多个编译页字段，不能拿它代替一处精修。
- `optimizeUnitRelations`：适合基于页面材料批量提出关系改进；仍要经过 review，不能把建议当作已经落库。
- `editUnitCompilePage`：适合已知单位的一处或一组精确修复；传 `relationHints` 时必须给最终完整数组。

## 七、常见错误

- `[[甲]]_守护着_[[乙]]`：`守护着` 未登记。应回到证据，选附录中含义确切的合法词；没有等价词就不写。
- `[[甲]]-位于-[[乙]]`：分隔符错误，应使用下划线。
- `甲_位于_乙`：端点缺少双中括号。
- `[[甲]]_相关_[[乙]]`：格式合法不等于事实正确；只有确实有关但无法归入更具体类别时才用“相关”。
- 只提交修正的一行：会覆盖掉未提交的旧关系。必须先读后整组替换。
- 留空数组：会让编译页保持关系提示缺失黄灯。确认无证据时写 `["无"]`。
