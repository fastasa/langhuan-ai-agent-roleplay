# 一键开玩世界

把用户的一句话展开成一份完整蓝图，再调用 `buildPlayableWorld` 完成正式落库。不要把普通全链路请求拆成一串低层写工具；编排工具只弹一次总确认，并按固定顺序留下逐阶段回执。

## 生成蓝图

1. 保留用户明确指定的题材、尺度、氛围、禁区和玩法重点。未指定处做相互一致的创作判断，不为无关细节打断用户。
2. 创建一个独立文档库树簇，并提供不少于 5 篇有实质正文的文档。至少覆盖：
   - 世界总览与核心幻想；
   - 地理、社会、阵营或文化；
   - 超自然、技术、资源或力量机制；
   - 可执行的游戏规则、限制、代价与成长方式；
   - 主要角色完整人设与相互关系；
   - 开场地点、初始矛盾和玩家怎样行动。
3. 每篇文档写独立标题、完整 Markdown 正文、可独立理解的摘要、2～8 个标签和合法 `semanticType`。不要只写目录、提纲或“待补充”。
4. 设计 3～6 个主要角色。每个角色必须有确定姓名、完整独立简述和头像画面描述；简述覆盖身份、外貌、性格、欲望、秘密、能力与限制、经历、世界关系、说话方式，以及与其他主要角色的可玩张力。还要为每名角色指定有意义的 `groupName`：优先复用语义完全合适的正式角色分组，没有合适分组时由工具新建；不得把新角色留在“默认”“未分类”等兜底组。
5. 设计世界名称、简介和 3～8 个匹配关键词。不要先自行创建世界；由工具读取当前世界后按确定性规则复用可信匹配，否则创建新世界。
6. 设计有名字的群聊会话，并把开场环境一次写完整：
   - 地点使用“大地点/中地点/小地点”三段格式，根据用户需要与世界观生成适合立刻开玩的具体地点；
   - 天气必须明确，优先服务开场氛围、人物行动和冲突，不得留空；
   - 用户没有特别指定时间时，不填写 `openingTime`，由工具在执行瞬间采用现实时间；没有特别指定流速时不填写 `timeRate`，由工具采用一倍速。只有用户明确提出架空时间或特殊流速时才覆盖默认值。
7. 设计一个世界专用的主要角色状态栏模板，使用 3～10 个 `text` / `number` / `list` 字段；字段应抓住本世界真正会变化、会影响行动的状态，不堆砌静态人设。为每个主要角色写完整开场值和状态栏用途说明，值必须逐一对应模板字段，不得漏项或添加模板外字段。
8. 设计 2～6 条可推进的叙事种子。种子必须有因果、当前进展、预期兑现、影响范围和知情边界；尚未发生的事情不得写成已发生事实。
9. 为每个角色与群聊分别写正方形头像 prompt。角色图保持同一画风但可一眼区分；群聊图表达共同舞台和核心冲突，不拼贴 UI、文字或水印。

## 执行

先确认本轮已经成功读取本 Skill，再调用 `buildPlayableWorld`，把完整蓝图放进同一调用。工具固定执行：

1. 生成文档库树簇、正文和编译页；
2. 生成并落库正式角色，至少 3 个成功才继续；按 `groupName` 复用或新建正式分组，并把所有成功角色写入正确分组；
3. 重新读取现有世界，可信匹配则复用，否则新建，并把新文档与既有挂载取并集；
4. 创建命名群聊，把成功角色全部加入，再把会话挂到目标世界；
5. 写入并回读开场时间、流速、三段地点和天气；
6. 读取正式 participantId，把所有新角色标记为在场；
7. 复用或新建世界专用状态栏模板，为每个主要角色生成并挂载一张开场状态栏；
8. 写入世界级叙事种子；
9. 只有以上内容全部成功后，才生成并设置角色头像与群聊头像。

不要在工具执行中途停下来问“是否继续”。用户取消总确认就停止，不换成低层工具绕过。

`buildPlayableWorld` 是可续建的聚合工具：每个阶段都会先回读同名树簇与文档、同名角色与分组、同名同成员会话、开场环境、状态栏模板与角色状态栏、世界内同名种子和既有头像，再只补缺失项。工具返回可重试错误时，必须在本轮使用完全相同的蓝图再次调用它；不要重新生成蓝图，不要调用 `toolsearch` 寻找低层续建链，也不要因为已经有部分正式内容就自行停止。相同蓝图在同一轮续跑沿用首次总确认。

## 完成门槛

只有回执同时给出以下真值，才可说“可以直接开始玩”：新文档 ID、至少 3 个角色 ID、每名角色的正式分组、世界 ID 与匹配/新建结论、文档挂载、会话 ID、时间/流速/三段地点/天气、全员在场、每名主要角色的状态栏 ID、叙事种子 ID，以及全部头像设置成功。

`buildPlayableWorld` 成功结果中的“正式完成回执”就是聚合工具在各阶段写后回读得到的验收真值。看到 `verificationStatus: verified_complete` 后，直接完成相关 TODO 并告诉用户可以开玩；不要再调用 `toolsearch` 寻找额外的角色、世界、会话、挂载、在场或种子只读工具，也不要因为没有第二套查询入口而把已完成任务留在进行中。

只有在处理旧任务、历史中断，或早期工具结果没有“正式完成回执”时，才调用 `readPlayableWorldBuildReceipt`，按精确世界名称或 worldId 只读补验收；世界下有多个会话时同时传会话名称或 sessionId。它会统一回读文档挂载、正式角色及分组、会话世界绑定、开场环境、全员在场、主要角色状态栏、叙事种子和全部头像。看到它返回 `verificationStatus: verified_complete` 后，必须把相关 TODO 标为完成；不要再继续 `toolsearch`。它返回 `incomplete` 时，只补回执列出的明确缺项，不得整链盲目重跑。

若内容主链或个别头像失败，优先用完全相同蓝图重试 `buildPlayableWorld`；工具会跳过已有头像，只补失败目标。明确区分“内容可玩”和“头像全部完成”。
