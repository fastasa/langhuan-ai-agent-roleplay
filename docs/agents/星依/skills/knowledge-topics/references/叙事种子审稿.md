# 叙事种子审稿

### 1. 叙事种子交稿怎样审字段与要求补交

适用条件：用户让星依开立、修改、检查剧本/伏笔/倒计时/幕后进程，或 `dispatchScriptwriter` 回报已经交稿时。星依即使没有直接读取编剧知识库，也要用本主题判断产物是否合格，不能只看绿色工具记录或“已完成”文字。

资料来源与写入目标：当前世界种子详情和当轮 `dispatchScriptwriter / submitNarrativeSeedChanges` schema 是字段真值；结果只能写进目标会话所挂世界的正式叙事种子。会话、世界、帷幕、成员和地图图纸都由代码提供，不在 directive 中猜。需要完整方法论时再派编剧按其知识库工作，星依不复制一份易漂移的全手册。

新建种子的模型字段固定检查 15 项：

1. `type`：合法类型枚举。
2. `title`：具体短标题。
3. `description`：描述是否满足张力要求：宏大、暴力、失去、性四个关键词自由组合
4. `cause`：已发生事实或明确设定形成的起因。
5. `currentProgress`：当前真实进展，尚未推进也要明确写出。
6. `expectedOutcome`：未来可能兑现的变化，不冒充事实。
7. `startTime`：唯一开始判断时点；优先 ISO 8601，虚构历法写完整日期和时刻。
8. `mapFeatureId`：只填已核实要素 id；没有时必须显式填空字符串。
9. `locationText`：严格 `大地点/中地点/小地点`，例如 `日本/东京/涩谷站前`。
10. `impactScope`：具体写可能影响的人物、关系、地点或世界状态，格式可以自由。
11. `status`：合法状态枚举；`ready_to_trigger` 只表示流动帷幕时间已越过 `startTime`，由系统自动写入，Agent 不得手工伪造；无事实不能提前写已触发/已解决。
12. `visibilityMode`：合法知情范围。
13. `allowFrontstage`：明确 `true / false`。
14. `participants`：数组；没有关联时明确 `[]`。
15. `links`：数组；没有关系时明确 `[]`。

禁止误用：不能要求模型填写 `unattendedOutcome / expectedTriggerTime / overdueTime / mapSheetId`。前三个字段已经退出；`mapSheetId` 由代码按目标会话当前图纸或世界默认图纸绑定。同一图纸不等于当前地点命中。超过 `startTime` 后，后台 Agent 根据现有因果、进展、预期结果、地点、影响范围和账本现场推断变化；当前帷幕地点命中 `mapFeatureId / locationText / impactScope` 且允许前台时才进入前台，否则只做后台变化，并可在独立新因果成立时派生完整新种子。

时间门验收：必须用会话的流动帷幕时间（虚拟起点、现实锚点、流速倍率）比较 `startTime`，不能只读静态 `virtualTime`。越时后应先看到 `ready_to_trigger / 待引爆` 与 `time_gate_reached` 账本；这只证明时间门越过。编剧应根据已越过时长检查人物、关系、地点和世界变化，正文/正式证据支持的才写进事实进展，没有证据的只能保留为候选。

字段确认边界：编剧可修改全部模型字段，但 `description / currentProgress / expectedOutcome` 是低风险内容维护；`type / title / cause / startTime / mapFeatureId / locationText / impactScope / status / visibilityMode / allowFrontstage / participants / links` 属于高风险结构变更，必须弹出用户确认。新建和删除始终确认。审稿时若看到高风险字段未经确认写入，不能判通过。

验收与失败下一跳：创建项缺任一字段、`locationText` 不是三段、空引用未显式表达、出现已删除字段或伪造 id，都不算交稿成功。`submitNarrativeSeedChanges` 应在同一次编剧运行里把具体字段路径退回；星依要明确要求编剧补齐后重交，不能把退回当完成，也不能用空数组掩盖。若本次运行最终仍因确定性字段错误失败，星依保留原始缺项，重发一份只要求补齐这些字段、说明格式并带上原交稿上下文的聚焦补交指令；只有超时或瞬时故障才按可重试回执延长时限或拆任务。

旧资料边界：正常审稿和派编剧只读取统一编排投影与正式世界种子，不读取任何旧浏览器剧本/TODO/倾向/私密指令/情境缓存。旧资料只能由用户在“旧编排迁移”工具中预览并勾选；待审查项不得由星依替用户自动确认或解释成已发生事实。
