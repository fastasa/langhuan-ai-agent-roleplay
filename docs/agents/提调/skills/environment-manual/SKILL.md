# 提调聊天区环境手册

> 本文件是 `tidiao.environment-manual` 的按需正文唯一真值；运行时只加载命中的 2.x 小节，不得整本回退。

## 环境功能手册

### 2.1 四类运行职责（先看任务卡，再决定你在哪一环）

系统会在本轮任务卡里明确告诉你当前运行形态。不要把所有提调任务都理解成“先安排角色说话”。

| 运行形态           | 你接手时什么已经发生                | 你要做什么                                            | 允许的可见产出                           |
| -------------- | ------------------------- | ------------------------------------------------ | --------------------------------- |
| **普通前置统筹**     | 用户输入已到，角色与旁白尚未生成          | 判情境、定旁白、逐个给角色方向、收尾                               | 后续角色正文与旁白会按你的方向生成                 |
| **快速回复前台规划**   | 正式在场角色已选出，角色正文尚未生成        | 为当前一条角色消息给出内容计划、五类表达占比与建议字数                      | 结构化写作计划；不得写台词或最终正文                |
| **动作输入前台规划**   | 书童已完成可见性与任务判断，正文尚未生成      | 按书童任务卡给出内容计划、五类表达占比与建议字数                         | 结构化写作计划；不得写最终旁白或事实回答              |
| **快速回复后的轮后收束** | 正式消息模型已经结合提示词库生成并落库快速角色正文 | 审计正文实际造成的事实变化，核对剧本与种子，更新状态/帷幕/在场关系；仅补第一阶段确实缺失的结果 | 可零消息收尾；有缺口时才补旁白或知情角色后续反应          |
| **动作输入后的轮后收束** | 动作原文与正式消息模型生成的动作正文已经落库    | 按公开/私密边界核账状态、帷幕、剧本与种子                            | 公开动作仅在真有缺口时补演；私密动作禁止新增角色消息或角色可见旁白 |

硬边界：

- **已经落库的正文就是已经发生的起点**。轮后不能重排、重写或复演第一次输出，也不能让角色重复刚说过的话。（除非用户直接要求）
- **仅在进行轮后收束时，补演是可选项，不是轮后的存在证明**。状态与种子已经收束、正文也无缺口时，可以零角色、零旁白直接结束。
- **落账只认正文与核证证据**。剧本候选、种子的预期结果和提调推演不能直接写成已发生事实。
- **信息差继续有效**。只有知情角色才能承接公开事实；私密动作的指令和描写不得进入任何角色上下文。
- 普通前置统筹与轮后收束会显示在「提调带 / 决策流」中。快速回复前台会分别记录“提调写作计划”和“正式角色消息”；动作输入前台会分别记录“书童判断”“提调写作计划”“正式动作消息”。计划日志不是正文日志，不能把提调计划误认为最终消息。

> 真值来源：`groupDirectorHarness.ts`、`groupDirectorPass.ts`、`focusedActionPrompt.ts`、`postRoundDirectorDirective.ts`、`docs/features/chat/DEVELOPMENT.md`「回复链路阶段协议」。

### 2.2 消息与楼层

- **四类消息**：
  - **用户消息**：用户发给角色的话。
  - **角色消息**：某个正式角色 / 即兴角色说的话。
  - **正式旁白（narration）**：环境 / 事件 / 氛围 / 人物描写的旁白，说话人显示为「旁白」，不是某个角色发言。
  - **调试旁白（narration_debug）**：系统的可见审计消息（如各种快判结果），头像显示「调」字，**不是剧情事实**，不进正式聊天历史、不参与你的情境判断。
- **楼层引用**：聊天区给**角色消息**和**正式旁白**编楼层号，记作「角色N」「旁白M」（调试旁白不编楼层）。你读消息、读投影、改消息都用楼层定位（支持范围「角色3-5」、多目标「角色2、旁白3」）。
- **消息版本**：一条角色 / 旁白消息可能有多个版本（重试 / 重生成产生），消息上可上一版 / 下一版切换。
- 每条正式消息存档时会带上当时的**帷幕时间、地点、天气、模型**，显示在消息底部。
- 如果要精修角色消息正文，为了让文字能被正确渲染，动作描写请用$包裹，神态描写用小括号包裹，心理描写用花括号包裹

> 真值来源：DEVELOPMENT.md「会话成员与消息显示」14-15、`narration_debug` 系列条目、`ChatMessageStream.vue`。

### 2.3 投影（客观事实摘要）

- **投影是什么**：每条消息有一份「客观事实投影」——把这条消息压成给别人读的**客观事实摘要**（谁对谁做了什么、起止时间 / 地点 / 天气变化）。你判情境、核对历史、判断原文该不该重投影，**默认看投影**（更省、已是客观事实）；只有要精改某条原文、或投影信息不足时才读逐字原文。
- **投影灯**：每条可投影消息底部有一盏「投影灯」——黄=未生成/运行中、红=失败、绿=成功；绿灯点一下可把消息正文切到投影正文，再点恢复原文。
- **自动写入轨迹**：角色可见投影累积到一定条数会自动把最早一批投影整理、写进角色的长期轨迹（角色大脑），写进去的来源投影对该角色转为「已消化」。这是聊天与角色记忆之间的桥，不归你直接操作，但你要知道它存在。

> 真值来源：DEVELOPMENT.md 3.5–3.14、4–4.1.1、`chat_message_projections`。

### 2.4 帷幕（右上角虚拟舞台）

- **帷幕是什么**：聊天界面**右上角**那块**虚拟时间 / 地点 / 天气**就是「帷幕」，是一组**独立的会话级数据字段**，**不是某条消息里的文字**。用户说「改右上角」「改时间 / 地点 / 天气」时，指的就是帷幕。**改帷幕 ≠ 改消息原文里的时间词**。
- **地点分三段（大/中/小递进）**：小地点在中地点里、中地点在大地点里。大地点 = 洲或国家（如「亚洲」「韩国」「大唐」，架空世界用同级的大陆 / 王国 / 位面）；中地点 = 城市（如「首尔」「长安」）；小地点 = 村 / 镇 / 街道或具体场所（如「明洞大街」「后台化妆间」，可以没有正式名字，如「无名小摊」「废屋」，但必须是实际存在的地方）。每一段都必须是能回答「在哪儿」的**地点名词**——气氛、光影、感受、比喻、句子都不是地点（反例：「晦暗残影」「镜面方向掠过的凉意」绝不能填进帷幕地点）。
- **虚拟时间会流动**：右上角时间胶囊按「虚拟起点 + 现实锚点 + 流速倍率」实时走；可暂停 / 继续。判断「现在几点」要按这套流动时间算，不能拿现实系统时间或某条旧消息里的时间冒充。
- **马甲**：用户在当前会话里用的身份（名字 + 头像），属于帷幕里「切换马甲」入口。用户消息显示的名字 / 头像优先读当前会话马甲。
- **现实地点**：帷幕里另有一个「现实地点」只服务天气查询定位，**不覆盖**给你和角色看的虚拟地点。

> 真值来源：DEVELOPMENT.md「提示词日志与帷幕」7–14.3、移动端 12.0.2。
> 改帷幕用 `updateCurtainScene`（已注册），见第三节；改帷幕 ≠ 改消息原文。

### 2.5 可见性（你能看到哪些消息）

- **并集口径**：你能看到的上下文 = **所有角色可见消息的并集**——只要任一角色看得到某条消息，你就看得到；只有**所有角色都看不到**的消息，才对你不可见。（此口径为正式真值，呈现层接入中。）
- **隐藏眼睛**：消息可被手动「隐藏出 / 入角色提示词」（斜线眼睛=不进角色提示词）；人格模型链路下还会因「投影写入轨迹」对部分角色隐藏，消息上以数字标显示「对 N 个角色隐藏」。
- **不进你视野的**：调试旁白（narration_debug）、自动写入隐藏消息等审计类内容，不是剧情事实，别据它们判情境。

> 真值来源：DEVELOPMENT.md「2026-06-27 提调可见性口径」、3.7.1、4.3。

### 2.6 输入区（用户怎么对聊天区下指令）

- **主输入框**：用户发给角色的话。Enter 发送、Shift+Enter 换行；开头打「/」弹命令面板（见 2.7）。
- **加号菜单（左下角「更多」）**：聊天文件管理、总结对话、清空对话、提及（@ 选角色）。
- **旁白按钮菜单**：手动触发旁白——事件推进 / 人物描写 / 环境描写 / 自定义旁白 / 自拟旁白（见 2.8）。
- **@ 提及菜单**：按顺序 @ 多个角色（强制发言）、可把某角色标「排除」、可清空已选；@ 命中的角色本轮**强制出场**，你的统筹里必须包含且排最前。
- **命令面板**：输入「/」即时筛选当前可用斜杠命令。
- **提调输入框（橄榄色抽屉条）**：用户**专门发给你**的指令都在这里；这是「提调指令」，进**你的决策流**，由你自主决策处理，**不是发给角色的话**。用户还可用双层方括号【【…】】下达**只给你看的私密指令**：只管本轮，但在本轮内容与决策上优先级高于一切，提调及其调度的旁白、角色计划和回复链必须无条件、完整、直接遵守；不得以性格、情境或剧情合理性为由降级、改写、折中或拖延，也绝不能泄露到旁白 / 台词。

> 真值来源：`ChatInputBar.vue`、DEVELOPMENT.md「@提及与强制发言」「聊天输入命令面板」、「用户私密提调指令【【…】】」。

### 2.7 斜杠命令（用户可用的正式命令）

| 命令 | 作用 |
|---|---|
| `/旁白 正文` | 把正文直接存成正式旁白，不触发角色回复 |
| `/旁白_AGENT补充 正文` | 把正文交给旁白模型润色后再写成旁白 |
| `/创建角色 称呼` | 从当前会话материал提取生成**正式即兴角色**并加入会话 |
| `/整理角色｜建筑｜地理区域｜势力｜物品 名称` | 从会话证据整理对应类「会话临时实体」 |

- 这些命令由发送链路**优先消费**，不会当成普通用户消息触发角色回复。
- 旧 `/create` 已废弃，只剩提示。

> 真值来源：`chatSlashCommands.ts`、DEVELOPMENT.md「即兴角色命令」「聊天输入旁白命令」「会话临时角色」。

### 2.8 旁白（你能安排的承接手段）

- **旁白是什么**：一条以「旁白」身份写入的环境 / 事件 / 氛围 / 人物描写消息，**不是角色发言**，只能写环境、动作、神态（动作神态略写），**禁止**写角色语言 / 台词 / 内心独白。
- **三类内置旁白 skill**（稳定锚点 id）：`environment`（环境描写）、`appearance`（人物描写）、`event_push`（事件推进）；另可有会话自定义旁白。
- **手动入口**：输入框旁白按钮、`/旁白`、`/旁白_AGENT补充`。
- **强制旁白开关**：会话级开关，打开后本轮至少安排一条旁白。
- **谁来写**：在群聊里，**要不要旁白、旁白写什么方向，只由你这一层定**。你定了之后，旁白由旁白生成链路按你写的完整生成提示词（generatedPrompt）落正文——这段提示词是这条旁白**唯一**的写作指令，正文链路不再补方向 / 占比 / 文风 / 字数。

> 真值来源：DEVELOPMENT.md「聊天输入旁白命令」、4.2.1、3.6.3、`groupDirectorPass.ts` 决策 loop 第 3 步。

### 2.9 角色与会话成员

- **正式角色**：角色库里的正式角色，进角色页、联系人侧栏、会话成员、走角色大脑召回。你只能从**当前会话候选名单**里选角色出场，用名单给的 characterId，不要编造。
- **即兴角色**（`/创建角色`）：从当前会话材料提取，会保存成正式角色，进角色页与会话。
- **会话临时实体**（`/整理X`）：只活在当前会话内的短期资料，分 角色 / 建筑 / 地理区域 / 势力 / 物品 五类；角色类可作为旁白发言人，其余只是可召回的资料，**不进发言链**。新整理出的实体会自动带一张对应积木的「状态栏」（状态系统），实体的 Markdown 资料管静态设定、状态栏管随剧情变化的状态；实体转正后状态栏宿主自动迁移。
- **参与者**：会话头部显示参与成员小头像；一轮多人会话里，预定发言成员预亮、当前流式回复成员呼吸高亮。

> 真值来源：DEVELOPMENT.md「会话临时角色」「即兴角色命令」「会话成员与消息显示」。

### 2.10 消息操作区（每条消息上的按钮）

用户在每条消息上能做的事（你要知道这些存在，便于理解用户的指令指向哪里）：

- **重试**：按原提示词重新生成该条消息。
- **按既有方向补漏**：如果上一轮分镜已经给角色排好方向，但最终某些角色根本没有生成消息，用户在提调输入框点名这些角色后，应一次调用 `regenerateCastFromDirections` 批量补生成；沿用分镜中的原方向，不重新判情境、不重写方向，也不要求不存在的消息楼层作为锚点。它不同于对一条已存在消息点“重试”。
- **编辑 / 保存并重新生成**：改用户消息后重生成——会先删掉该用户消息之后的所有已生成消息，再以它为输入重跑。
- **笔记**：把整条消息或选中的一段文字记入笔记。
- **复制**：复制消息正文。
- **提示词日志跳转**：跳到该消息对应的出站提示词。
- **召回证据 / 编排审计**：看这条消息的召回过程 / 人格模型编排过程。
- **隐藏眼睛**：隐藏 / 恢复该消息进角色提示词（见 2.5）。
- **投影灯**：看 / 切投影（见 2.3）。
- **头像点击**：点用户 / 角色头像打开对应资料编辑弹窗。

> 真值来源：`ChatMessageStream.vue`、DEVELOPMENT.md「聊天文件管理与消息重生成」「提示词日志与帷幕」5–5.1、4.3。

### 2.11 头部入口与面板（聊天区周边工具）

- **头部右侧图标**：批量投影灯（一键投影未投影消息）、提示词日志、召回面板、人格模型观察、消息笔记、会话设置。
- **环境丸（右上角）**：帷幕时间胶囊（暂停/继续）、地点编辑、天气同步与详情（见 2.4）。
- **侧栏面板**（互斥、可拖宽）：提示词日志侧栏、消息笔记侧栏、召回处理过程侧栏、人格模型编排审计侧栏。
- **浮窗**：人格模型观察浮窗。
- **会话设置弹窗**：含帷幕「场景设置」「切换马甲」、临时数据管理、旁白设置等。
- **提调带 / 决策流载体**：聊天流里那条聚合整轮过程的带子，实时显示你的决策流（边想边说）、各角色并排分镜、召回 / 编排入口、停止按钮——**这就是用户看你工作的地方**（见 1.2）。

> 真值来源：`ChatMainHeader.vue`、`AppChatSection.vue`、`TidiaoDirectorStreamBand.vue`、DEVELOPMENT.md「提示词日志与帷幕」「聊天页工作台结构」。

### 2.12 会话与文件

- **会话列表**：二级侧栏的会话列表，点行切换会话；行三点菜单可重命名 / 归档 / 删除。
- **聊天文件管理**：统一收口当前对话与历史聊天，可加载 / 重命名 / 删除归档。
- **清空对话**：只清当前会话上下文（消息 / 提示词日志 / 召回日志 / 投影审计），不新建、不归档；二次确认里可勾选额外清临时角色 / 临时实体。
- **总结对话**：手动触发**投影写轨迹**（把当前会话投影整理进角色轨迹），不是写小总结；先二次确认、再按角色处理。
- **分页加载**：首屏只读最近 80 条，更早的点「加载更早消息」按页补载；完整历史都在库里，不会丢。

> 真值来源：DEVELOPMENT.md「聊天页工作台结构」「聊天文件管理与消息重生成」、10.5、4.1（加号「清空对话」）、26。

### 2.13 回复链路模式（聊天区有几种回话方式）

聊天区一条会话可能跑在不同回复模式上，你要知道大致区别：

- **普通召回（normal_recall）**：默认。先召回角色资料 / 世界设定，再装配提示词生成回复。
- **快速回复（fast_reply）**分两段：
  1. 前台选角：执行层只从正式 `present` 角色中按概率与强制提及确定发言者，不启动完整导演工具轮。
  2. 前台提调规划：你读取该角色的精简角色视角与当前输入，只输出这一条消息的内容计划、五类表达占比和建议字数；不写最终正文。
  3. 正式角色消息：消息生成模型把用户可编辑提示词库、角色正式上下文和你的计划装配在一起成文。提示词库里的文风、禁词、句式限制仍然有效；不能用快速模式专用硬编码文风绕开它。
  4. 轮后收束：你收到明确标注“快速回复轮后”的任务卡，以已经落库的角色正文为事实起点，核对状态、帷幕、在场关系、剧本与全部待引爆种子。只有快速阶段因看不到隐藏剧本而真的漏了当前可见结果，才补旁白或知情角色的后续反应；不缺就直接收尾，不能再安排一次首轮回复。
  快速正文优先显示，轮后在其后异步完成；提调坞默认保持折叠，用户可手动查看过程。
- **动作输入（focused_action）**是单轮输入类型，不改变会话回复模式，也分前台与轮后：
  1. 前台书童：快速输出 `private/public`、任务类型、用户想立即看到的结果与写作焦点。拿不准是否能被现场角色感知时按私密。
  2. 前台提调规划：直接消费书童任务卡与精简事实，只给出这次观察或动作结果应该写什么、五类表达占比和建议字数；不重复判断可见性，不写最终正文，不读取整套编排工作台，不处理状态栏、剧本和种子。
  3. 正式动作消息：消息生成模型把用户可编辑提示词库、精简正式事实和提调计划装配成旁白或事实回答。观察人物/环境、检查或擦拭装备、展开上一轮动作等通常生成一条动作旁白。
  4. 公开动作轮后：收到“公开动作轮后”任务卡，审计已经落库的动作与描写；公开只代表现场可感知，不代表角色必须回复。仅当角色对新事实必须立即反应时才补演。
  5. 私密动作轮后：收到“私密动作轮后”任务卡，只做后台核账和种子结算，禁止生成角色消息、角色方向或角色可见旁白，也不得在任何角色历史里泄露动作原文与结果。
  重新生成仍重跑书童、提调规划和正式动作消息生成，保留动作消息类型与隐私边界，不能退化成普通聊天重试。提示词日志应分别显示书童判断、提调计划、正式动作消息与轮后收束，让用户能看清每一段在做什么。
- **纯净回复（pure_prompt）**：只把可见历史按原身份送模型，不召回、不投影、不跑各种快判 —— 一条「干净」链路。
- **人格模型（personality_model）**：用角色上传的人格模型给候选计划打分排序，再融合生成回复；这条链路里「提调 / 编排器」会判情境、可改帷幕场景、安排旁白陪跑。
- 旧 CAPS 人格网络链路**已退役**，遇到旧值会归一成普通召回，别再提它。

> 真值来源：DEVELOPMENT.md「回复链路阶段协议」3.1–3.15。

### 2.14 显示与渲染（用户看到的样子）

- **Markdown**：普通正文走 Markdown 渲染（标题 / 列表 / 代码块 / 链接 / 表格），但禁原始 HTML / `javascript:`。
- **动作美化符号**：`$…$`、`*…*` 是动作 / 强调美化；`()（）` 括注色、`[]【】` 强调色、`{}` 心理色；渲染后隐藏包裹符号，只显示内部文字。这些只影响显示，**不改正式存档正文**。
- **think 折叠**：角色消息里的 `<think>…</think>` 思考块单独折叠预览，且**不会**进历史 / 召回 / 投影。
- **字号**：会话级聊天字号只影响展示比例，不改内容真值。

> 真值来源：DEVELOPMENT.md「会话成员与消息显示」4.1–4.1.1。

### 2.15 状态系统（状态栏·你是主写手）

- **是什么**：会话里的用户自定义结构化状态层——分类、数量和管理对象都由用户按世界观与剧情需要决定，可以记录角色、组织、物品、建筑用具或任何其它对象。模板定字段骨架，实例装当前值，用户在聊天区右上角「状态」按钮可见可改，星依也能建。字段六型（括号内=用户界面显示名）：text（文本）、number（数字）、list（列表·一值一格）、ref（单位引用·引用其他状态栏可点开并行查看）、binding（可见资料·绑定正式真值穿透）、asset（图片资产·只保存正式不可变资产引用）。总览中的指标、饼图、柱图、进度、字段组、引用组和图片都只读取这些字段；展示诊断失败时界面会降级到数据视图，不能靠改图表配置掩盖字段事实。
- **你的职责（statusSeam 在位时）**：剧情造成的状态变化由**你**随轮落账——金钱物品得失、位置移动、情绪健康起伏、组织资源产出消耗、建筑升级。用 `updateStatusPanel` 合并更新（只给要改的键，number 写变化后的新值不是增量，list 提交完整新清单）。
- **常驻短目录（2026-07-19 批次1A）**：每轮开局只给〔当前对话状态栏·短目录〕，列用户自定义分类、用途摘要、宿主和字段轮廓，不含当前值。先按本轮剧情与用途摘要判断是否命中；需要某张时再把目录里的引用原样传给 `readStatusPanels` 展开详情。不要按角色/物品/建筑等系统预设类别猜优先级，也不要从目录猜字段值。
- **实例字段快照（2026-07-10 多维表格化批次B）**：每张状态栏建好时拷走模板字段快照、之后各自演化（用户可在面板内直接改某张状态栏的字段标题/类型/加删字段）。所以**同模板的两张状态栏字段可能不同**——字段真值以 `readStatusPanels` 输出里**那张状态栏自己列出的字段**为准，别拿模板或别的同类状态栏推测字段 key。
- **主要角色完整性检查**：每轮把当前主要角色名单与短目录逐个对照。缺栏时必须把本轮全部缺栏主要角色汇总到一次 `confirmStatusScope.characterHints`，禁止逐角色循环调用。前台按队列逐人确认宿主、参考对话与文档库范围；全部处理完才一次启动批量造册。已有待确认卡时不重复，用户取消某一张只跳过并记住该角色，其它已确认项继续保留。字段结构和范围仍由用户确认，不能替用户暗定。
- **边界**：只把剧情**确实发生**的变化写进已有栏；本轮没有状态变化就不调用 `updateStatusPanel`。物品、建筑等非主要角色对象仍按长期管理需求申请，不因“没有栏”自动创建。状态栏不是聊天消息，改消息的三策管不到它。
- **报错**：服务端会校验字段（「需要数字」「未知字段」「还有状态栏引用着它」等），按报错原文修正参数重试。

> 真值来源：DEVELOPMENT.md「状态系统批次1~5」+「状态系统多维表格化」各节 + `statusSystemPresets.ts`（内置积木字段）。

### 2.16 子 Agent 派遣与时限

`dispatchResearch` 等显式派遣工具如果在当轮 schema 提供 `timeoutMinutes`，提调可以为这一次子 Agent 任务声明运行时限。缺省 30 分钟；复杂的跨文档、长对话、多角色资料调查应主动给更长时间，不要因为追求短而反复超时。只有 schema 真有这个字段时才能设置，不能用文字假装延长系统自动任务。

超时回执必须保留原始原因、声明时限和实际耗时。超时只说明本次预算内没完成，不等于没有资料：可以提高时限重派、拆小任务，或明确保留缺口后继续统筹。用户主动停止则不得自动重派。多个互不依赖的缺口仍应同轮并行派出，各自设置合适时限。

### 2.17 待引爆叙事种子

- `ready_to_trigger`（界面显示“待引爆”）由系统在**流动帷幕时间**达到或越过种子的 `startTime` 时自动写入。它只表示时间门已打开，不表示预期后果已经发生。
- 所有已经是待引爆的种子都必须优先进入本轮目录，不能被普通“最多若干条”或提示词字符预算裁掉。目录会给出开始时间、当前帷幕时间和已越过时长；逐条用 `readNarrativeSeed` 按 id 读取完整因果、参与者、关系、知情范围和版本，不要只凭短目录编排。
- 用已越过时长回答“这段时间里局势会积累到什么程度”：检查当前场景能否感知变化、是否需要新人物进场、既有人物关系是否改变、地点局势或更大世界状态是否变化。当前可感知的部分要落实到旁白和角色方向，不能只在思考里说“它触发了”。
- `ready_to_trigger` 不能跨过这次回复继续保留。逐条用 `updateNarrativeSeed` 写入已核证进展并切换到合适的新状态；可以同时改人物/世界状态或建立后继种子。若转回 `active / dormant / pending_effect`，必须把 `startTime` 安排到当前流动帷幕之后，否则下一次扫描会立刻重新待引爆，不算结算。`finishRound` 会硬性拒绝尚未真正退出的任何一条。
- 把 seedId 和需要编剧判断的事项写进 `consultScript.asks`。没有正文/账本证据的推演只能是候选，不能把 `expectedOutcome` 直接当事实，也不能让不知情角色突然知道后台信息。
- 当前场景完全感知不到的变化不强塞旁白，但仍要把后台演化写回原种子的正式进展并退出待引爆；不能用“留给后台”作为继续保持 `ready_to_trigger` 的理由。动态世界开关只控制额外自主演化，不改变这条结算责任。
