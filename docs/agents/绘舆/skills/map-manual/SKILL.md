# 绘舆地图详细手册

> 本文件是 huiyu.map-manual 的按需正文唯一真值；通用核心六节只存在于 ../../通用知识.md，本文件不复制。

## 一、你在画什么：矢量舆图的三种要素

地图由要素（feature）组成，每条要素属于一张图纸（sheet），有三种几何：

- **region（面）**：多边形轮廓——山脉、森林、草地、高原、水域、城区。这是地图的主体，形状一经画定持久固定、面积可信（用户会看到实测面积）。
- **path（线）**：折线——河流、道路、街道、城墙。推荐给起点/终点各挂一个既有要素（`from`/`to` 带 `featureId`），系统会自动把端点吸附到那个要素的边界上并生成自然蜿蜒（河流挂海洋/湖泊就不会断连）；只有挂不上时才直给顶点数组。
- **marker（点）**：单坐标——建筑、地标、渡口、组织驻地、**角色当前位置**。

每条要素还有图层归属：**terrain（地形层）**=自然地物（山/林/草/原/水/河），**civic（人文层）**=人造物（城/村/路/街/建筑/地标/角色）。用户可以切换只看地形或只看人文，归错层会导致要素在错误的视图里出现/消失。

## 三、系统硬校验总览（画错了系统会拦，不用你自己记着防）

> 口径：下面这些约束已经写进代码，落笔时系统会自动校验——画错了不会静默通过，会拦下来并给出具体建议（如"改用桥""改内流湖""改索道/天梯"），照回执改就行，不用自己死记硬背每条边界数值。这节讲的是"代码卡什么"；剩下每节讲的是"怎么画才对味"，两者不重复，别在这节找美感指导。

**落笔前立即拦（硬门层·不用扫全图，只看这一笔自身+明确挂接的少数邻居）**：

1. **可画地表**：每个类目只能画在陆地/水域/不限三选一（如 road 只能画陆地）；违反→硬拒+建议改用桥或换地方。
2. **量级区间**：region 半径必须落在该类目的常见量级区间（与第四节比例量级表同一张表）；超界直接拒绝生成。
3. **坡度滑动窗口**：road/street/trail/canal 沿线按滑动窗口（约 2 倍格宽或 500m 取大者，防止台阶地形单格算出假峭壁）计算最陡坡度，超类目硬上限（road 150%/street 100%/trail 300%/canal 15%，初版取宽松值只拦荒谬地形）→硬拒+建议改索道/天梯或改道；接近但未超硬上限的只进体检提醒，不拦落笔。
4. **河流有源有尾**：river/canal 落笔前会真的跑一遍水文合法性校验——终点只差一点点（≤150m 内有水域）系统自动帮你吸附收尾；明确非法（逆坡爬升/找不到归宿）→硬拒，回执里附一条 D8 建议改道线，也可以把终点改成内流湖。
5. **桥接岸双条件**：bridge 两端点必须落在陆地上（端点落在水里时系统会先尝试自动吸附到最近的合法接岸点），且路径必须真的跨了水（跨一块面状水域，或跨一条河流/运河路径，满足其一即可）——两条都满足才放行，任一不满足都硬拒。
6. **闭合自动补**：border/wall 用 `pts` 出口画环时，首尾没接上系统会自动补闭成环，不拒绝，也不用自己反复对齐最后一个点。
7. **嵌套自动裁**：山/林/草/高原/丘/漠/沼/冰/雨林九类互为嵌套关系——新画的与已有同族地形部分重叠时，海拔更高的一方自动裁进对方内部（回执注明）；海拔不比对方高却部分重叠→硬拒（需要整体挪开或抬海拔）。这正是"由低到高分批拔升"画法（第十三节）的机制保证。
8. **山中水体尺寸帽+海拔继承**：water 与 mountain 重叠不是被禁止，是条件放行——短轴≤6000m 且面积≤所叠山体面积的 25%，超帽硬拒；没超帽就原地放行，且没显式给 elevationM 时自动继承所叠山体的海拔（避免水文网格里山腰凭空出现一个 0m 深坑）。画在两脊之间/山体边缘凹处的山谷手感更好，但这条只是体检软提示，不硬判。
9. **阶段保护（Lock）与 terraform 改造通道**：staged 阶段制作画里，已确认阶段的要素后续阶段不能再改它的几何/位置，也不能删除（改名/换 style/挂 links 不受限）；确需大改（隧道/运河/削坡）就在写调用里带 `override:'terraform'`，会转人工审批，批准了才放行。这不是把内容冻结只读——查询工具（elevationAt/surfaceAt/featuresAlong）与 auditMap 永远能看到全部已画内容，只是普通笔刷写不动它。
10. **同一约束连续违规熔断**：同一条硬门连续撞上 3 次（哪怕每次坐标/参数不同，只要是同一条规则），系统会放弃这一笔、写一份人工求助回执——别在同一处反复试参数，换个思路或先用空间查询工具查一遍再动笔。

**违禁重叠一览（region×region，未登记的类目对缺省放行，不需要逐对穷举）**：water×urban / water×water / water×farmland / water×desert / urban×urban / urban×farmland / desert×swamp / desert×jungle / ice×jungle 九对禁止重叠；water×mountain 是上面第 8 条的条件放行，不在禁止之列。

**体检层（auditMap 事后扫描，只报不拦，绝不会替你删除/挪动要素或改探索范围）**：

| 编号 | 检查项 | 严重度 | 一句话 |
|---|---|---|---|
| MAP-1010 | 悬空端点 | warning | 河/路/桥等类目的端点没接上任何合法目标；autofix 会顺手吸附 ≤150m 的 |
| MAP-1020 | 违禁重叠 | warning | 命中上面禁叠表的两个 region 确实几何重叠了 |
| MAP-1030 | 未闭合环 | warning | border/wall 的 `pts` 环首尾没对上；autofix 会自动补闭 |
| MAP-1040 | 出探索范围 | info | 要素落在了 explored 范围外，画完记得 expandExplored |
| MAP-1050 | 尺度异常 | info | region 半径超出常见量级区间（存量数据常见，只提醒不拒） |
| MAP-1060 | 流向非单调 | warning | 河/运河沿线在填洼后地形上出现逆坡爬升 |
| MAP-1070 | 坡度分档超标 | warning | 沿线最陡坡度进入该类目的最高分档，建议人工复核要不要改道 |
| MAP-1080 | 山中水体山谷提示 | info | 山中水体存在（已通过尺寸帽）时提醒宜置于山谷，仅供参考 |
| MAP-1100 | 路河无桥 | warning | road/street/trail 与河/运河相交处附近没找到桥（渡口/浅滩本就合法，别一看到就慌） |
| MAP-1110 | 城墙跨水 | warning | 城墙与河/运河相交，提示宜设水门 |

## 五、怎么画才优秀（布局原则）

1. **先读后画**：动笔前必先 readMapSummary 看清现有格局（谁在哪、多大、相互方位），新要素的位置必须与已有要素的方位关系自洽——任务书说「临澜城以北的山」，就真的画在它北边，距离按比例常识定。
2. **造形工具优先**：面状要素用 drawMapRegion 的参数化造形（中心+半径+形态+seed），不要自己硬编多边形顶点。形态选择：山林湖泊用 blob（有机），规整湖面/盆地用 ellipse，城区/地块用 rect，山脉成条专用 form=ridge（画法见第十三节）。同 seed 永远同形状——重画同一要素想保形状就复用原 seed。
3. **密度与留白**：地图不是填色游戏，大片留白（未命名的原野）是正常的；只画剧情到过、提到过的地物。一次任务通常只新增 1~4 个要素。
4. **山有走向**：山脉优先用 form=ridge 画出条状主脊（画法见第十三节），并给 spine 脊线（2~5 个点描出走向）——spine 不是符号布阵用的，用途是供大区域名沿脊斜排显示，走向准确名字才排得自然。
5. **命名贴世界观**：名字从任务书/剧情事实里取，没有现成名字时按世界观风格起（武侠世界别起「阿尔卑斯」）。
6. **LOD 分级**：街道/单座建筑给 minScale≈0.1（放大才显示），城镇级 0.04~0.06，大地物不设（恒显示）。避免缩到大陆视野时满屏建筑名。
7. **连接靠挂接不靠手抄**：河流入海、道路进城这类"两处地物相连"的场景，用 `from`/`to` 挂既有要素的 `featureId`，端点由系统吸附到边界——手抄坐标是断连（河海不接）的主因。系统还会在放置面状/点状要素时自动避开重叠（水域/城区/山体互不侵占），撞了会自动挪开并在回执里说明，不必自己反复试坐标。

## 七、角色位置与状态联动

- 角色当前位置=category `character` 的 marker，links 挂 `{ hostType: 'character', hostId: <角色id> }`。
- 剧情里角色移动 → 用 updateMapFeature 挪该 marker 的坐标（不要删了重建，id 保持稳定）。
- 建筑/组织类 marker 的 links 可挂对应状态栏（panelId），用户点图标能展开状态卡（联动层后续实装，links 先如实挂上）。

## 八、多图纸口径

默认全部画在主图纸（created_at 最早的一张）。只有物理不连通的空间（异世界/位面/梦境）才建新图纸——新图纸间不共享坐标系。拿不准时不要建新纸，问题写进交稿摘要让提调定。

## 十二、画城结构法（城市不是几条线·2026-07-11 wall 类目拍板）

一座城至少由三层组成，缺一层观感就散架：

1. **城区面（必有）**：`drawMapRegion category:'urban'`——城市的占地范围，用户看图第一眼认出"这里是城"靠的就是这块面。超大帝都可以画多块 urban（核心城区一块+外围城区带一到数块），注意 urban 与 urban 相邻排布不重叠。
2. **城墙线（有墙才画）**：`drawMapPath category:'wall'`——实线厚重专属样式，**不许再拿 road 凑数画墙**。环形墙用 `pts` 出口画环，首尾没接上系统会自动补闭（第三节第 6 条）；直墙段/关隘可开口。墙应贴着它围护的 urban 城区边缘走，不许悬在空地上围着虚无。
3. **地标点（点名才画）**：`drawMapMarker`——任务书/草案点名的建筑落 marker，且按第十一节铁律**不设 minScale**。

配套规则：
- 道路从城门/城区边缘出发连向别的城/渡口，别让大城孤零零没有一条对外道路。
- 城靠水建时（设定说了才画），河流走向要与城区量级匹配（贯穿或绕过整个城区，见第十一节）。
- 只有环带没有城区面 = 违例：环形墙内部/环带之间必须有 urban 面撑着，否则用户看到的只是几个空环。
- 城墙与河/运河相交处宜设水门——不设也不拦，只是体检会提醒一句（MAP-1110，见第三节）。
- 城门（gate）落在城墙开口与道路交点；farmland 画在城郊、不进城内；滨海城常配 port marker 贴岸；街道网格贯穿、官道对外延伸的具体画法见第十三节。

## 十三、笔刷画法手册（每类目怎么画才对味·谓词化）

> 词汇表（第二节）只说"这是什么"，这里说"怎么画"——参数名+数值档位+依托关系，不写抒情散文。

region（面）：
- `mountain`：成条画优先 form=ridge（ridgeTo+ridgeWidthM+ridgeTaper）。嵌套高海拔内核=在外层内部再画一条更窄的 ridge（宽度约外层 40~50%）、elevationM 更高、长度明显短于外层、两端收进外层内——系统有配套硬门：与既有地形部分重叠且海拔更高时自动裁进外层（回执注明），海拔不高于外层的部分重叠会被硬拒（整体挪开或抬海拔），细节见第三节第 7 条。
- `hill`：小而缓——rxM/ryM 取区间低段（数百米~数千米），elevationM 给较低值（缺省 400）。
- `plateau`：走默认造形（blob/ellipse）即可，与森林/草原同规则，不需要特殊处理。
- `forest`/`jungle`：森林取中等 roughness；雨林（jungle）比森林更大片，可更贴近水域画。
- `grass`：默认 blob；人文视图不会因为叫"草地"就自动归绿（只有 mountain/hill/forest/jungle 或 elevationM≥600 才归绿桶），要绿就挂高一点的 elevationM。
- `desert`：大块平滑——roughness 取低值（0.05~0.15），避免碎边。
- `swamp`：贴水域画——中心紧邻或部分接壤 water region 边缘。
- `ice`：高海拔/极地——elevationM 给高值（缺省 4500），常配大跨度。
- `water`：海岸破碎用 coastRoughness（参考画廊三档：0.2 低碎/0.5 中碎/0.65 高碎），可选 isletCluster 生成伴生小岛群（散布在海岸边缘内外）；规整湖泊改用 form=ellipse。山中水体（与 mountain 重叠）系统按尺寸帽条件放行（短轴≤6000m 且面积≤所叠山体 25%，超帽硬拒，见第三节第 8 条）——未显式给 elevationM 时自动继承所叠山体海拔，落笔位置宜挑两脊之间或山体边缘凹处的山谷（体检只给软提示，不硬判）。
- `urban`：宜方正——form=rect + roughness≈0.02；超大城区拆多块 urban 相邻排布、互不重叠。
- `farmland`：近城分块——挨着 urban 边缘画，不进城内，尺度小于所属城区。

path（线）：
- `river`：有源有尾——from 挂山地/湖泊，to 挂海/湖/干流；meander 取高值（缺省 0.5）；长度须与流经城区同量级；可选 widthProfile 定制沿程宽度剖面（不给则按缺省自动生成变宽水体：源头约 6m→入海口约 160m，两岸不对称碎边由系统生成，不用手画）；河体与海/湖同色系，不再有独立"河水色"。
- `road`：连接语义——from/to 挂城门/城区/渡口等既有要素，城外互相延伸，不悬空。
- `street`：城内正交网格——起步 2 横 2 纵、贯穿整个城区，minScale≈0.1。
- `wall`：规整不歪扭——meander≤0.1 或改用 arc 出口画圆弧关隘；环形墙用 `pts` 首尾同点闭合（漏合系统会自动补，见第三节第 6 条）；贴 urban 边缘走。
- `border`：沿天然屏障走——挂山脊/河流等既有要素当依托；圈领地时首尾闭合成环。
- `canal`：人工近直——meander 取低值（缺省 0.1），连接两处水域；可选 widthProfile（不给则按缺省近恒宽，源头约 10m→末端约 14m）；同 river 与海/湖同色系。
- `trail`：细弱蜿蜒——meander 可比官道更高（缺省 0.35），走人行小道路线。
- `bridge`：短且近直——meander 取最低（缺省 0.03），两端必须跨过水域、落在两岸陆地（不能只搭一半悬空）；端点若落在水域内，系统会先尝试自动吸附到最近的合法接岸点，实在找不到才硬拒（第三节第 5 条）。

marker（点）就位口径：
- `port`：贴海岸线落点。
- `gate`：落在城墙（wall）与道路（road）的交点上。
- `inn`：沿官道（road）分布。
- `tower`：沿疆界（border）或城墙（wall）分布。
- `capital`：落在都城 urban 区域内。
- `mine`/`cave`：贴山地（mountain/hill）落点。
- `ruin`/`temple`/`castle`：按任务书指定位置放，无特殊坐标偏好。
- `ferry`：贴内河/湖岸，量级小于 `port`（`port`=海港，`ferry`=小渡口）。
- `building`/`organization`/`landmark`/`character`：用法见第一节/第七节，不重复。

elevationM（海拔）通用口径：
- geometry 里的物理真值，不是呈现参数——驱动地形视图色带（第 8 档色带）与人文视图山地/陆地判定。
- 类目缺省表（第二节已列层归属·具体数值见工具描述）大多数情况够用，不必每次显式给。
- 需要显式给的场景：嵌套拔升内核（山脉内核比外层更高）、高原台地想贴近雪线、明确设定的雪线以上地形。

由低到高分批拔升（陆地地形族通用手法·机制见第三节第 7 条）：
- 整个陆地地形族（山/林/草/高原/丘/漠/沼/冰/雨林）都按"嵌套海拔面"处理：两块地形部分重叠时，海拔更高的那块会被自动裁进更低的那块内部（回执注明）；海拔不高于对方的部分重叠会被硬拒。
- 因此画复合地形时按海拔**由低到高分批下笔**：先铺大片低海拔基底（草原/荒漠等），再往基底上叠中层（丘陵/森林/高原），最后点最高内核（山脉主脊/雪峰），每一层要么整体落在下层内部、要么 elevationM 明显高于下层。
- 反着画（先画高的再补低的基底）会让后画的低地形撞上"部分重叠且海拔不高于对方"的硬拒；已经画反时优先整体挪开或调整海拔，不要反复原地试参数。

## 十四、宏笔刷（一笔生成一整套关联要素·长版手册）

宏笔刷是"语义决策交给你、自然形态与合法性交给算法"的高层画笔——四件都是确定性生成器，内部逐要素自动过第三节的硬门，只有全部合法才落库。v1 只能新建，不支持带 id 重画；生成结果不满意就用单笔工具修补，或换个 seed 整套重生成（同 seed 恒形）。

### `drawMountainChain`（山脉链）——仅地形阶段可用

- **适用场景**：一次性生成一整条带主脊+支脉、高海拔核心自动嵌套裁进的山系，比逐条 drawMapRegion 摆独立山块更快出"主脊高两翼低"的层叠观感。
- **参数**：
  - `name`（必填）：名称前缀，各要素自动加"·底座/核心/支脉N"后缀。
  - `anchors`（必填，≥2 点）：走向骨架坐标串，描出山脉链整体走势，2~6 点足够，不用太密。
  - `chainWidthM`（必填）：底座满宽（米），对照第四节 mountain 量级。
  - `baseElevationM`（可选，缺省 1400）：底座海拔。
  - `coreElevationM`（可选，缺省=底座+1600）：高海拔核心海拔。
  - `coreWidthRatio`（可选，缺省 0.45）：核心宽度=底座宽度的比例。
  - `coreLengthRatio`（可选，缺省 0.5）：核心覆盖主链弧长的比例，居中截取。
  - `spurProbability`（可选，缺省 0.5）：每个候选点生成支脉的概率。
  - `spurAngleDeg`（可选，缺省 35）：支脉相对脊线法向的角度扰动上限（度）。
  - `spurLengthRatio`（可选，缺省 2.2）：支脉长度=底座满宽的倍数。
  - `seed`（可选，缺省用 name）：造形种子，同 seed 永远同形状。
- **与单笔取舍**：想要一整条山脉链（主脊+支脉+嵌套高海拔核心）一次成型选它；只想加一座独立小山、或需要逐笔精细控制单个山体形状，用 `drawMapRegion`（可配 form=ridge）。
- **阶段归属**：仅地形阶段（terrain）可用；水系/人文阶段不装配本工具。

### `drawRiverSystem`（水系树）——仅水系阶段可用

- **适用场景**：从一个源头坐标一笔生成整棵水系树（干流沿地势自动追踪下坡+若干支流以自然汇入角挂接），比手动逐条画河省心，且天然顺流合法——不会自己试出一条逆流河。
- **参数**：
  - `name`（必填）：名称前缀，干流/支流自动加后缀。
  - `source`（必填 `[x,y]`）：源头附近坐标，系统从这里沿地势自动追踪下坡路径，不必精确到山谷底。
  - `tributaryTier`（可选，缺省 medium）：支流数量档，`low`=1 条/`medium`=2 条/`high`=3 条。
  - `seed`（可选，缺省用 name）。
- **与单笔取舍**：想要一整套带支流、河宽自动按 Strahler 分级定档的水系用它；只想画一条精确走向已知的单独河流，用 `drawMapPath category:'river'`。
- **阶段归属**：仅水系阶段（water）可用。

### `drawCityLayout`（城区路网）——仅人文阶段可用

- **适用场景**：一次性生成城区面+中心到各城门的主干道+贯穿全城的街道网格（可选城墙城门），比分别画 urban/street/wall 更快，且街道天然贯穿不留断头。
- **参数**：
  - `name`（必填）：城市名，用作 urban 区与各要素名称前缀。
  - `center` 或 `anchor`（二选一必填）：城区中心坐标，或相对既有要素的锚点定位。
  - `radiusM`（必填）：城区半径（米），对照第四节 urban 量级。
  - `orientationDeg`（可选，缺省 0）：主干道走向角度（0=正东西/南北向）。
  - `streetPattern`（可选，缺省 grid）：`grid`=方正网格；`organic`=有机弯曲。
  - `blockSizeM`（可选，缺省按 radiusM 自动估算）：街区尺度基准。
  - `meander`（可选，缺省 0.3，仅 streetPattern=organic 生效）：有机档弯曲度。
  - `gateAnchors`（可选，缺省按东南西北四方位自动推导边界交点）：对外连接锚点坐标。
  - `wallEnabled`（可选，缺省 false）：是否生成环形城墙+城门 marker。
  - `seed`（可选，缺省用 name）。
- **与单笔取舍**：想要一整座城（区域+主干道+街道网+可选城墙）一次成型用它；只想加一栋建筑、单条街道，或在已有城区上做局部微调，用单笔 `drawMapRegion`/`drawMapPath`/`drawMapMarker`。
- **阶段归属**：仅人文阶段（civic）可用。

### `drawInterCityRoad`（城际道路）——仅人文阶段可用

- **适用场景**：两地之间的道路，代价寻路自动避陡坡+途经水域处自动接岸置桥，比手动摸索桥的位置更快。
- **参数**：
  - `name`（必填）：道路名。
  - `from`/`to`（均必填）：起止点，`{at:[x,y]}` 直给或 `{featureId}` 挂既有城区/marker。
  - `via`（可选）：必须途经的坐标点数组。
  - `grade`（可选，缺省 trunk）：`trunk`=官道（更直更缓）；`trail`=小径（更能爬坡）。
  - `seed`（可选，缺省用 name）。
- **与单笔取舍**：想要两地间自动避坡、遇水自动置桥的道路用它；已经确定精确走向、不需要自动选线，用单笔 `drawMapPath`。
- **阶段归属**：仅人文阶段（civic）可用。

何时用宏笔刷 vs 单笔（总口径）：
- 要一次成型一整套结构（整条山系/整棵水系/整座城的路网/带桥的长路）→ 用宏笔刷，快且合法性由算法构造保证。
- 只加一个要素、微调既有内容、或位置关系特殊需要逐笔控制 → 用单笔画笔（drawMapRegion/drawMapPath/drawMapMarker）。
- 宏笔刷 v1 只能新建不能带 id 重画；生成结果不满意时用单笔工具修补或删掉重生成（换 seed 换形状，同 seed 恒形）。

## 十五、草案剪影清单画法（submitLayoutDraft 结构化产出·2026-07-12 地图草案剪影可视化计划）

> 由来：草案确认卡曾是千字文（summary+facts+assumptions+missingInfo 逐条罗列长文），用户反馈"晕字"。草案轮（submitLayoutDraft）现在应同时交回 `sketches`（结构化剪影清单）：每项是一个改动的粗糙几何+置信色+卡片文案，前端画在地图上让用户直接点选，不用再逐行读长文。不给 `sketches` 仍走现行纯文字确认流程（零回归，只是体验不如剪影直观）。

- **summary 压到≤5行**：给了 `sketches` 时，summary 只写一句话总览这次要新增/改什么，细节全部挪进每项的 `card`，不要逐条复述剪影内容。
- **每个改动项拆成一条 sketch**：`kind`（region/path/marker）+`action`（add/modify/delete）+粗糙几何 `sketch`+`confidence`（`ready` 绿=确定可落笔／`confirm` 黄=需确认／`risk` 红=高风险）+`card`（`change`/`basis`/`risk`，每字段≤3短句）。`action` 为 `modify`/`delete` 时必须带 `targetFeatureId` 指向现有要素。
- **剪影只示意"位置+规模+意图"，不是最终形状**：几何越粗糙越好——正式形态、造形细节交给落笔轮的真笔刷（drawMapRegion/drawMapPath/drawMapMarker）与第三节硬门重新生成；剪影本身不入库、不受量级/坡度等约束校验，别在草案阶段较真细节轮廓。
- **坐标口径同正式笔刷**：单位=米，同一套世界坐标系（第四节量级表照常适用），不要为了"草案"另起一套简化坐标或换单位。
- **region 优先椭圆**：`sketch.center`+`rx`/`ry` 画个粗略椭圆即可；只有轮廓明显不规则（如沿海岸线的狭长半岛）才用 3~8 点的粗多边形（`sketch.points`），点数越少越好。
- **path 用折线**：`sketch.points` 给至少 2 个点描出大致走向，不用精细描摹蜿蜒。
- **marker 用单点**：`sketch.center` 一个坐标即可。
- **互斥备选不做专门字段**：想给用户"选 A 还是 B"的方案，就出两个 `confidence:'confirm'`（黄）的 sketch 项，各自 `card` 说明利弊，让用户在地图上点选采纳一个、弃用另一个——不要自己在 summary 里问"选哪个"。
- **不确定的项目一律标黄或红，别都标绿**：`confidence:'ready'` 意味着"这一项很确定，用户大概率会直接采纳"；只要牵涉假设、或任务书没说清的量级/方位，就用 `confirm` 或 `risk`，让用户在地图上一眼看出哪些需要多看一眼。
