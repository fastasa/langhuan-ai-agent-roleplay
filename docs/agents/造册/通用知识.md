# 造册基础制作规范

> 运行时 Skill：`zaoce.basic-authoring`；由造册 Agent 常驻读取。这里是正文唯一真值，TypeScript 只负责装载与审计。

- 状态栏只承载需要持续查看、更新或被后续流程引用的正式状态；先读现有状态栏与正式资料，再决定新增、更新或不处理。
- 优先更新同一事实的既有状态栏，禁止仅因名称或措辞不同重复造册。
- 分类由当前世界、用户要求与正式资料决定，不预设角色、物品、地点等固定门类；无法确认归属时保留通用分类并说明依据。
- 字段保持少而稳定：每个字段都应有清楚含义、可追溯来源与后续更新价值，不为一次性描述堆字段。
- 字段可读性是硬门：每个字段必须有非空、可区分的 `label`；number 字段只要正式资料已经给出单位，就必须把纯单位写进 `unit`。禁止把单位塞进数值，禁止根据字段名、数值大小或常识猜造“人、平方公里、货币”等单位；正式单位缺失时保留空 `unit`，并在交稿中明确列为“单位待确认”。
- 任何总览都必须脱离编辑表格仍能读懂。禁止发布只有大号数字、没有字段名的指标；每个数值块都要在附近显示它是什么，正式单位存在时还要显示单位。图表标题、分类标签和资源名称不能依赖用户回到数据视图反推。
- 每张状态栏都维护 description，概括“这张栏记录什么”；普通值变化不改摘要，只有用途或字段语义改变到旧摘要失真时才同步修改。
- 值来源逐字段标记为 observed、inferred、creative_default 或 unknown。资料不足时可以给符合角色扮演语境的 creative_default 保守初值，但它必须可编辑、与已知事实相容，关键关系或状态不可伪装成已确认事实。
- 正式 ID、宿主、scope、权限、版本和已发生事实只能来自正式上下文或工具回执，禁止用 creative_default 补造。
- 现成模板只是可复用材料，不是建栏前提。没有适配模板时，必须根据任务目的、已确认字段和正式资料原创一个最小够用的新模板，并把 `template + panels` 放进同一次 `applyStatusPanelBatch` 原子提交；绝不能以“无模板”为由放弃、反复空调批写或提交失败稿。未知字段值可以明确保留“未明”，模板不存在不算阻断。
- 单张或多张状态栏都应在一次 applyStatusPanelBatch 中结构化提交；同一任务涉及多个宿主、多张新栏或多项修改时，先把全部已确认对象汇总到一个批次，不要按角色循环调用。只有某组校验冲突且各组确实互不依赖时才拆批。读取整批回执，失败就按错误修正后重试。写入成功不是自动终止，确认任务满足后才调用 submitPanels 统一交稿。
- `submitPanels` 只允许汇报本轮已经真实写入的状态栏；状态栏名单以 applyStatusPanelBatch 的真实事务回执为准，调用时只要把完成摘要写清，`panels` 可省略，不要为了重复抄名字浪费一轮或造成假失败。只设计模板、只写文字方案、批写零状态栏或批写仍报错都不能交稿。真正的阻断只包括正式宿主、确认范围或写入接缝缺失等无法在当前权限内修复的问题。
