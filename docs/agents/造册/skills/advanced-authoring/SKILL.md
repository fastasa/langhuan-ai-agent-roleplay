# 造册进阶制作手册

> 运行时 Skill：`zaoce.advanced-authoring`；只按准确 selector 读取一个二级小节。这里是正文唯一真值，TypeScript 不保留镜像正文。

## advanced_template｜自定义模板

- 仅当现有状态栏结构无法稳定表达一类会反复出现的对象时，才设计自定义模板；一次性对象直接按当前资料造册。
- 先定义模板适用范围、承载对象与每个字段的业务含义，再决定字段名称、类型、默认值和更新规则。
- 字段名称应跨对象复用，默认值必须与“未知”“空缺”“尚未发生”区分；不要把展示文案当成不可变的业务值。
- 新模板需兼容既有面板：能映射则沿用既有字段语义，不能映射时明确新增理由，避免同义字段长期并存。
- 交稿前用至少一个当前对象检查模板是否可填写、可更新、可阅读，并删除只为该对象特制的过拟合字段。

## cross_panel_reference｜跨状态栏引用

- 只有目标状态栏已经存在且身份可唯一确定时才建立引用；先读取目标栏，禁止用相似名称猜测目标。
- 引用保存稳定身份或正式引用键，展示名称只用于可读性，不得用自由文本冒充真实关联。
- 明确关系方向与数据归属：谁持有引用、谁维护事实、目标删除或改名后如何处理，避免两边重复维护同一事实。
- 写入前检查循环引用、互相覆盖与一对多歧义；无法消除歧义时保留普通字段并说明待确认关系。
- 批量变更时先创建或确认被引用目标，再写引用方，最后复读两端验证关系闭合。

## rich_media_scaffold｜富媒体脚手架

- 脚手架只声明可承载的媒体槽位和元数据，不得把尚不存在的图片、音频或附件写成已拥有资产。
- 每个槽位明确来源、替代文本、空状态与加载失败回退；没有正式资源时保留可识别的空位，不编造链接。
- 业务事实与展示资源分开保存：移除媒体后，状态栏仍应能用纯文本读懂并继续更新。
- 媒体字段只保留稳定元数据与正式引用，临时渲染参数、编辑器状态和一次性提示词不进入长期状态。
- 交稿前同时检查有媒体、无媒体和失效媒体三种状态，确保布局与语义都不会阻断普通造册。
- 图片字段必须使用 `valueType=asset`；值只写 `{ assetId, kind:"image", alt, caption? }`，禁止写 base64、临时 URL、本地绝对路径或 CSS。
- `media` 展示块只绑定 asset 字段，`fit` 只能是 `contain/cover/pixelated`。没有已上传正式资产时只搭槽位，不伪造 `assetId`。

## visual_carrier_selection｜状态载体选择

- 先判断阅读任务，再选载体：查一个数用 `metric`；看占比用 `donut`；比较同单位多项用 `bar`；看完成度用 `progress`；逐项核对用 `field-list`；钻取实体用 `reference-list`；看图片用 `media`。
- 表格/数据视图永远保留为编辑与核对底座；总览只做第二种读法，不复制或改写字段真值。
- 同一块只回答一个问题。不要为了“丰富”把所有字段都图表化；文本、异单位数字和不可比较的资源不硬塞进同一图。
- 可读性是出稿硬门：每个 `metric` 都必须填写非空 `title`，优先直接采用正式字段 `label`；派生指标的标题必须说清计算结果。`donut / bar / progress` 也必须用标题或自身标签说明主题，禁止让“合计”、裸数字或条形长度代替字段名。
- 单位只从正式字段元数据或用户明确口径取得。字段已有 `unit` 时，`metric / bar / progress` 必须显示相同单位；`donut` 没有独立单位槽，已知单位写进可见块标题，例如“人口构成（人）”。单位未知时禁止猜造：单指标可用 `subtitle` 标记“单位未登记”，比较图则先退回 `field-list` 并在交稿中报告元数据缺口。明确为比例、倍率等无量纲值时可不填单位，但标题仍不可省略。
- 展示配置使用 `schemaVersion: 1` 与 `blocks`；每块必须有稳定、唯一的 `id`，`span` 只能是 1/2/3。
- 禁止输出任意 HTML、脚本、CSS、组件名或公式字符串；只使用协议允许的 block 与表达式。
- 提交前逐块做“脱离上下文阅读”检查：枚举所有可见数字，确认附近能看见字段名/业务含义；正式字段有单位的，再确认附近能看见同一单位。任一指标标题为空、已知单位被漏掉或分类标签含糊，都先修正再提交。

## categorical_chart｜分类图表

- `donut.total` 必须是同一口径总量；每个 variant 的 segments 必须同单位、非负，且合计等于 total。
- `donut.title` 必须命名统计对象，不能只依赖圆环中心的“合计”；单位已知时写成“统计对象（单位）”。每个 variant 的 `label` 必须说明分类维度，每个 segment 的 `label` 必须是用户能直接理解的分类名。
- 需要补足剩余分类时显式使用 `remainder`，例如成年人口=`总人口-儿童-老年`；不要让渲染器静默补差或裁负数。
- 同一事实可以配置多个 `variants`（如人口“按性别/按年龄”），切换只属于本地视图状态，不写回业务字段。
- 表达式只用：`field`、`constant`、`sum`、`difference`、`remainder`、`ratio`、`count_refs`。`field` 只能引用 number 字段。
- 交稿前逐 variant 验算合计；资料不一致时保留正式值并让界面显式报错，不能擅自改数凑图。

## resource_dashboard｜资源与经营看板

- 同单位、同量纲资源可放一个 `bar`；库存与容量用 `progress`；关键总量用少量 `metric`。不同单位应拆块并标明 `unit`。
- 资源字段保持纯 number，单位写字段/展示元数据，禁止把“48000 木材”整个塞进数值字段。
- 每个关键总量 `metric` 都要用正式字段名作为可见 `title`，不得只摆一个大号数字；正式字段有单位时同步填写块 `unit`。资源 `bar` 必须有说明比较口径的标题、逐项资源名和共同单位，不能让用户靠位置猜“这是什么、按什么计量”。
- 多个资源字段的单位都为空时，不得仅凭数值把它们画进同一条形图；先保留为 `field-list`，并在交稿中列出需要补登记的单位。只有正式资料证明它们同单位、同量纲后才能比较长度。
- 只展示可支持决策的资源：短缺、储备、产出、容量或升级需求。自由文本清单继续留在数据视图，不为做图而虚构数字。
- 经营看板先给总量/风险，再给比较项，最后给升级或关联对象；推荐 1-2 个指标块 + 1 个比较块 + 必要的列表/引用块。
- 条形长度以当前块最大有效值为相对基准；不得把负数、空值或不同单位伪装成可比较数据。
